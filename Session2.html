Studi Kasus: Algoritma Buruk vs Baik

❌ Buruk (Ambigu)

1. Masak mie.
2. Kalau sudah matang, tiriskan.

Kenapa buruk? Tidak jelas berapa lama masak, bagaimana cara meniriskan.

✅ Baik (Jelas)

1. Didihkan 400ml air.
2. Masukkan mie, masak 3 menit.
3. Angkat dan buang air.

Kenapa baik? Semua orang pasti melakukan hal yang persis sama.

Aturan Menggambar Flowchart

  • Arah Alur: Dari atas ke bawah, kiri ke kanan.
  • Start & End: Wajib punya satu Start dan minimal satu End.
  • Decision: Selalu beri label Ya/Tidak (Yes/No) di tiap cabang panah keluar.
  • Garis Panah: Jangan menyilang agar mudah dibaca.

Pseudocode

Bahasa perantara antara manusia dan kode. Tidak punya aturan baku, tapi harus logis.

MULAI
  INPUT nilai
  JIKA nilai >= 75 MAKA
    OUTPUT "LULUS"
  SELAIN ITU
    OUTPUT "REMEDIAL"
SELESAI

Anatomi Pseudocode

MULAI                     // Titik mula
  INPUT harga, jumlah      // Minta data
  total = harga * jumlah   // Proses hitung
  OUTPUT total             // Tampilkan hasil
SELESAI                   // Titik akhir

Gunakan kata kunci yang jelas, beri indentasi (spasi masuk) untuk blok di dalam JIKA atau ULANGI.

Pemetaan: Pseudocode ke Python & C

Pseudocode

JIKA nilai >= 75 MAKA OUTPUT "LULUS" SELAIN ITU OUTPUT "REMEDIAL"

Python

if nilai >= 75: print("LULUS") else: print("REMEDIAL")

C

if (nilai >= 75) { printf("LULUS"); } else { printf("REMEDIAL"); }

Ide yang sama, ditulis dalam bentuk berbeda. Jika pseudocode benar, menulis Python/C jadi mudah.
